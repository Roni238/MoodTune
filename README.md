# MoodTune
MoodTune — это веб-приложение, использующее возможности ИИ психологом. Бот не дает бездумных советов, а слушает, анализирует ваше состояние, выслушивает и помогает структурировать мысли, предлагая техники релаксации и поддержку.

## Основные возможности
Контекстный чат с ИИ: Бот помнит историю диалога (в рамках сессии) и отвечает с учетом предыдущих сообщений.
Персонализация: Адаптация ответов под пользователя раз в 10 сообщений бот собирает информацию о пользователе в "Досье" и важные факты и события о пользователе для персонализации ответов
Онбординг: При первом входе пользователь заполняет анкету (имя, стиль общения), что помогает ИИ настроиться на волну пользователя.
Мгновенная синхронизация: Данные профиля и чата обновляются в реальном времени
Адаптивный интерфейс с состояниями загрузки, плавными анимациями и удобным полем ввода

## Технологический стек
Frontend: Vue 3 (Composition API), TypeScript, Pinia (State Manager), Vue Router, Vercel (Deploy)
Backend: Supabase (PostgreSQL, Auth), REST API
AI / LLM: Google Gemini (Flash/Pro), Gemini Embeddings, Векторные базы данных (pgvector)
Архитектура: Feature-Sliced Design (FSD)

## Архитектура проекта

### Frontend (Vue.js)
Клиентская часть построена на Vue 3 с архитектурой FSD (Feature-Sliced Design).

Авторизация и Сессии:
 * Используется Supabase Client для управления сессией.
 * Перавая отрисовка моментальная, рендерится компонент оверлея с динамическим приветствием (в зависимости от времени суток), на время проверки работы сервера и авторизации
 * Неавторизованный пользователь направляется на страницу входа.
 * После входа — принудительный онбординг (заполнение профиля), затем доступ к чату.
 * Для защиты и правильных редиректов в router.ts реализованы миддлвееры
State Management (Pinia):
 * User Store: Хранит данные пользователя, профиль и сессию. Обновляется через Supabase (слушаем изменения в таблице profiles)
 * Chat Store: Кеширует сообщения текущей сессии. При переходе на профиль и обратно чат не перезагружается.
UI/UX Детали:
 * Базовый ui-kit (Кнопка, чекбокс, инпут, текстареа, лоадер), у всех компонентов несколько вариантов стиля (передаются через props) и разные состояния (Hover, Active, Disable, Loading).
 * Компонент Textarea: Автоматическое увеличение высоты при вводе.
 * Скролл чата: Автоматическая прокрутка вниз при появлении нового сообщения или ответа ИИ.
 * Индикатор набора текста: Во время генерации ответа отображается статус "Печатает...", а кнопка отправки блокируется.
 * Разбивка ответов: Длинные ответы ИИ автоматически разбиваются на мелкие сообщения для улучшения читаймости и создания живой переписки
 * Компонент оверлея, первое что видит пользователь на время рендера приложения, авторизации и загрузок, отображает приветствие стилизованное под время суток, в случае ошибки сервера, отобразит сообщение об этом, при успехе, уведомит и правно закроется
 * Для создания динамики, создан утилитарный класс с живым фоном и плавной анимацией

### Backend (Supabase)
Вся серверная часть построена на Supabase — это база данных + авторизация

 * Таблица users: Стандартная таблица для аутентификации (управляется Supabase Auth)
 * Таблица users_profiles: Связана с users (one-to-one). Хранит:
  - Имя пользователя
  - Предпочитаемый стиль общения (формальный/дружеский)
  - Информация о пользователе (хобби, проблемы)
  -  флаг прохождения онбординга
* Таблица chats: История сообщений между пользователем и ИИ
* Таблица mood_logs: хранит логи об экстренных ситуациях (Деструктивные намерения, опасные ситуации и другое)
* Таблица user_summaries: досье пользователя? что не указывал пользователь но ии собрал из чата, хранит информацию, пол, возраст, важные события его жизни и другие данные
* Векторная база знаний knowledge: дополнительный справочник для повышения качества ответов, используются rag с заполнеными embedding полями дли поиска и идут в к сообщению как дополнительные знания, требуется для создания логических инструкций к ситуациям, конкретные кейсы и и решение, примеры событий и метаданные, примеры: 
 - тригер: самокритика => анализ его чувств => стратегия: Самосострадание + техника: Объятие
 - тригер: паника => стратегия: Заземление + техника: Цветовое заземление
 - тригер: самоповреждение => стратегия: safety_plan, приотерет: high, (пример критической ситуации, ии будет держать контакт и уверять, что лучше поможет реальный человек, предоставлять телефоны поддрежки)
 * Сообщение принимается в Edge Functions, обрабатываются embedding поиски и формирование истории и досье, собранные материалы собираются в dynamicInstruction, которые передаются в гемини для ответа:
  const geminiResponse = await postGemini(dynamicInstruction, history.data || [], message )
  в postGemini ответ анализируется, прошле ли он по лимитам и защитным фильтрам, если что-то не так, запрос повторяется с другой моделью
  
### LLM & RAG
Мозг проекта — это гибридная система с использованием RAG

Статичный слой (System Instruction):
 * Приоритетный алгоритм реакции
 * Технический инструментарий и ЗАПРЕТЫ (не давать медицинских диагнозов, не поддерживать деструктивное поведение)
 * Обработка команд и защита от "бреда" (непонятные запросы — просьба уточнить)
 * Базовый стиль общения, роль и задачи
Динамичный слой:
 * Данные разбиты на категории: эмоции, паттерны мыслей, терминология, техники
 * Каждая запись имеет векторное представление (embedding), созданное через gemini-embedding
 * Как это работает: При получении запроса пользователя мы ищем в этих таблицах самые "близкие" по смыслу записи (через косинусное расстояние) и подставляем их в промпт как контекст
Обработка запросов: 
 * Собранный контекст + Системная инструкция + Текст пользователя отправляются в Gemini
 * Реализован цикл перебора моделей: если текущая модель не отвечает (ошибка/таймаут), система автоматически переключается на следующую модель из списка (от лучшей к самой старой), гарантируя получение ответа
 
 
## Начало работы

Клонируйте репозиторий:
```
git clone https://github.com/Roni238/MoodTune.git
cd MoodTune
```
Установите зависимости:
```
$ npm install
```
Настройте переменные окружения в .env, для доступа гемини api ключ указывается на бекенде (в supabase):
```
VITE_SUPABASE_URL=https://***
VITE_SUPABASE_ANON_KEY=sb_***
```
Запустите дев-сервер:
```
npm run dev
```
